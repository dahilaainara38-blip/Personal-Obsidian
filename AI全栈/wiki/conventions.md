# 操作约定

> 这份文件记录**你（人）的操作偏好**，Agent 每次开工都应读。
> 它不是死的：每次你觉得 Agent 做得不对，就把纠正写在这里，它就会一直生效。

## 收录偏好

- **素材一律放 `raw/` 根目录，不放 `资料/`，不放别处。** 中文文件名 + 全角标点会在入库时改成英文 kebab-case（CLI 与脚本处理不了全角问号）。
- **一次一份，保持介入。** 先让 Agent 给 3-5 条 takeaway 并讨论，再落盘。不要静默批量收录。
- 收录后 Agent 必须报告：改了哪些文件、发现了什么矛盾、有哪些疑点。
- 素材优先收**一手来源**：官方文档 > 源码 > 作者博客 > 二手解读。二手来源必须标注。
- 时效性内容（版本号、API 签名、价格）必须写核实日期，超 3 个月自动视为待核实。

## 内容偏好

- **面向"我要用它把东西做出来"**，不是面向考试。少写定义，多写"什么时候用、什么时候别用、坑在哪"。
- 代码优先给**能直接跑的完整片段**，不给残缺伪代码。
- 选型类结论必须给**决策条件**（"如果 X 就用 A，如果 Y 就用 B"），不能只说"各有优劣"。
- 涉及国内落地（阿里云、DeepSeek、通义、私有化部署）单独标出来，这是你的实际场景。

## 待补充（用一段时间后回来填）

- [ ] 你常用的技术栈组合？（Spring Boot 版本、JDK 版本、前端框架）
- [ ] 学习目标是面试导向、项目导向还是技术选型导向？
- [ ] 是否需要中英双语术语对照？
- [ ] 是否需要把实践代码单独抽到 git 仓库，wiki 只留链接？

## 疑点与待验证

- 这些偏好是初始化时按"Java + AI 全栈学习者"的典型画像推测的，尚未经过真实协作验证。前 3 次收录后应回顾修订。
