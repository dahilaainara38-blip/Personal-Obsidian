# 素材摘要 · 什么是缓存雪崩、击穿、穿透（小林coding）

> 一句话：三者都是"请求绕过缓存打到数据库"，区别在原因——大批 key 同时失效（雪崩）、单个热点失效（击穿）、数据根本不存在（穿透）。

- 来源：https://www.xiaolincoding.com/redis/cluster/cache_problem.html · 收录 2026-09-18
- 原始素材：`raw/redis-cache-avalanche.md`

## 关键论点

1. **雪崩**（大量 key 同时过期 或 Redis 宕机）：①过期时间加随机值打散；②互斥锁（同一时间只允许一个请求重建缓存，要有超时）；③后台更新（缓存不过期+后台定时刷/消息队列通知失效即刷，配合**缓存预热**）；④宕机场景：熔断/限流保数据库、主从+哨兵高可用集群。
2. **击穿**（单个热点数据过期）：互斥锁；或热点不过期+后台异步更新/到期前提前刷新。**击穿是雪崩的子集**。
3. **穿透**（缓存和数据库都没有）：①API 入口校验非法参数；②缓存空值/默认值（要配较短 TTL）；③**布隆过滤器**——位图数组 + N 个哈希函数置 1；查询时任一位为 0 则必不存在，全 1 则"可能存在"（有误判、单向：说不存在就一定不存在）。Redis 自带支持。
4. 判别口径：雪崩/击穿时**数据库里有数据**，缓存恢复即缓解；穿透是**两边都没有**，无法靠重建缓存解决。
