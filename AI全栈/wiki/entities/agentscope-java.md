# AgentScope Java

> 阿里开源的生产级多 Agent 框架（Java 版），主打 ReAct 范式与"能上生产"的工程能力。

## 核心要点

- **生态位：独立的多 Agent 框架层**，不绑定 Spring，但可与 Spring 集成。
- 与 [[spring-ai]]（基础设施）、[[langchain4j]]（应用工具箱）不在同一层，更多是**叠加**而非替代。
- 主打差异点集中在**生产化能力**：分布式部署、多层记忆自动压缩、HITL 人类在环、会话恢复、多租户隔离 —— 这些恰是其他框架普遍缺失的部分。
- ⚠️ **当前页可信度标注为 low**：仅有二手检索信息，未核实官方文档。

## 细节

### 声称的能力（均待核实）

| 能力 | 说明 | 为什么重要 |
|---|---|---|
| ReAct 范式 | 思考-行动-观察循环 | [[agent]] 的主流范式 |
| 双层 Agent 架构 | 粗粒度与细粒度编排分离 | 复杂任务的可控性 |
| 分布式部署 | Agent 可跨节点运行 | 单机的 Agent 跑不了生产 |
| 三层记忆 + 自动压缩 | 长对话不爆上下文 | 长任务必备 |
| HITL 三态权限 | 自动 / 需确认 / 禁止 | 高风险动作的合规底线 |
| 会话恢复 | 崩溃后从断点继续 | 20 步任务崩了不用重来 |
| 四级多租户隔离 | 租户间资源与数据隔离 | SaaS 场景刚需 |

**如果这些属实，那么它的定位就是"Java 版的生产级 Agent 运行时"，补足的正是 [[agent]] 里列的那几条硬要求。**

### 版本与选型提示

> ⚠️ **版本待核实。** 初始化检索同时看到 1.0.x 与 2.0.x 两种说法且互相冲突，**必须以 java.agentscope.io 官方为准。** 有资料提示早期 1.0.0 的 API 与后续版本差异很大，老教程不可信。

### 什么时候考虑它

- 要做**多 Agent** 且要上生产（不是 demo）
- 需要会话恢复、人类在环、多租户这类企业级能力
- 团队能接受较陡的上手曲线

### 什么时候别选

- 只是要接个模型、做个 RAG —— 杀鸡用牛刀
- 强依赖 Spring 原生体验 —— 优先 [[spring-ai]]
