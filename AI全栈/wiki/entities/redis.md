# Redis

> 一个开源的内存数据结构服务器，通常架在真实数据库前面做加速层。更准确的定位是「数据结构服务器」而非「键值数据库」。

## 核心要点

- **本质差异在"按数据结构组织"，而不是"存字符串"。** 它从一开始就以数据结构的方式组织数据，不靠迭代或排序处理 —— 这是它相对 Memcached 的根本分野。
- 典型职责：承接**不常变更且高频访问**的数据，以及**低关键性但高频**的数据 —— 会话、排行榜、聚合分析。
- 它模糊了缓存与数据存储的界限：加上插件与 HA 配置，某些场景下可以直接当主数据库用。
- 命令执行仍是单线程；Redis 6.0 起支持**多线程 I/O**，但执行的单线程模型没变。
- 定位判断：**它是"让系统变快"的组件，不是"让数据变可靠"的组件。** 要可靠性必须额外配持久化与复制，且都有代价。

## 细节

### 与 Memcached 的对比

| 能力 | Memcached | Redis |
|---|---|---|
| 亚毫秒延迟 | 是 | 是 |
| 数据分区 | 是 | 是 |
| **高级数据结构** | 否 | **是** |
| 多线程架构 | 是 | 6.0 起多线程 I/O（执行仍单线程） |
| **快照 / 复制 / 事务** | 否 | **是** |
| 发布订阅 / Lua / 地理空间 | 否 | 是 |

结论：**纯 KV 缓存且不需要持久化 → Memcached 够用；需要数据结构或可靠性 → Redis。**

### 部署形态演进

```
单实例（快，无 HA）
  → 主从复制（读扩展 + 数据冗余）
    → Sentinel（自动故障转移 + 服务发现）
      → Cluster（水平分片，突破单机内存上限）
```

详见 [[redis-cluster]]。

### 持久化

三种选择：无持久化 / RDB / AOF / RDB+AOF 混合。核心机制是 fork + 写时复制。
详见 [[redis-persistence]]。

### 与 AI 工程的交叉点（待验证）

- Redis 生态有 **RediSearch**，支持向量检索，理论上可作为 [[rag]] 的向量库使用
- 若成立，则对已有 Redis 的团队是低成本接入 RAG 的路径 —— 但**本文未涉及，需单独查证**其向量能力、维度上限、性能表现
